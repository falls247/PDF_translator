# PDFの翻訳とHTML化

対象言語、成果物の場所、原文の構成に関するユーザーの指定を優先する。未指定の場合は依頼文の言語に訳し、原文と図表を照合しやすい構成にする。内容全体の翻訳を要求された場合は要約で代用しない。

このプロジェクトでは、既定の入力場所を `inputs/`、成果物の保存先を `outputs/<元PDFの拡張子を除いたファイル名>/` とする。HTMLは既定で `index.html` とし、関連する画像などもそのフォルダ内にまとめる。抽出テキスト、画像一覧、検証用スクリプトなどの中間生成物は `executed_files/<元PDFの拡張子を除いたファイル名>/` にまとめる。成果物の検証後、`inputs/` から処理したPDFを `executed_files/` に移動し、HTMLから原PDFを参照する場合は移動後のパスを使って再検証する。入力以外の場所から指定されたPDFは勝手に移動しない。同名の成果物フォルダ、中間生成物フォルダや移動先ファイルがある場合は上書きせず、保存先をユーザーに確認する。処理または検証が未完了なら入力PDFは移動しない。

1. `pdfinfo` でページ数・暗号化・ページ寸法を確認し、`pdftotext -layout` と必要に応じて `-raw` で本文を抽出する。抽出結果をページ単位で点検し、複数段組の読み順、行末ハイフン、脚注、数式、ページをまたぐ文の欠落や誤りを原PDFで確認する。抽出できないページは画像化して視認または適切なOCRを使い、確実に読めない部分を明示する。
2. `pdfimages -list` で埋め込み画像を調べ、図を抽出する。ベクター図や画像以外の表は対象ページを描画して必要な範囲を収集するか、情報を保ったHTML表として再構成する。画像の透過マスクと図本体を区別し、図の切り抜き、読みやすさ、順序を確認する。図の中の未翻訳ラベルは明示し、日本語の説明を付ける。
3. 見出し、全段落、図表とキャプション、脚注、付録、書誌情報を対応づけて訳す。数式や固有名詞、単位、識別子、数値は正確に維持する。書誌情報は出典を同定できる原題を残す。図表中の例文が実験対象なら、必要に応じて原文も併記する。原文の誤記を訂正する場合は原表記と変更を訳注に記し、推測による補完を隠さない。
4. HTMLには言語指定、文字コード、見出し階層、図の代替テキスト、図表の説明、目次を付け、幅の広い表を小画面で読めるようにする。外部サービスへの送信や公開は依頼の範囲と権限に従う。
5. 原PDFと照合し、全ページと図表番号、数式、脚注、参考文献、付録を確認する。HTMLの構造、文字化け、画像・ローカルリンク・ページ内リンクを検証し、可能ならブラウザで表示確認する。未翻訳箇所、確認できなかった点、原文の問題、実施した検証を成果物または報告に明記する。
